title: Guides
description: Wiring mockingpug into a specific framework or the CLI on its own
---

Framework- and tool-specific setup. Each guide assumes you've already
run through [Getting Started](/docs/getting-started) and have a
`mock/` directory with at least one entity.

- [React](/docs/guides/react): mocking a REST API in a React SPA via MSW.
- [Vue](/docs/guides/vue): the same MSW browser worker for Vue (and any non-React SPA — Svelte/Solid/vanilla).
- [React Native](/docs/guides/react-native): React Native / Expo via MSW's native server, plus `mpug codegen` for Metro.
- [GraphQL](/docs/guides/graphql): a GraphQL API auto-generated from the same tables and store.
- [Next.js](/docs/guides/nextjs): a real App Router Route Handler, backed by the same query resolver.
- [Vite plugin](/docs/guides/vite): auto-discovery of `mock/**` as a virtual module.
- [CLI](/docs/guides/cli): `init`, `doctor`, `generate`, `migrate`, `codegen`, `types`, `docs`, cloud `login`/`link`/`pull`/`open`, and more.
- [MockProvider & MockDevtools](/docs/guides/devtools): optional components for worker lifecycle, live runtime editing, and the floating panel (React and Vue).
